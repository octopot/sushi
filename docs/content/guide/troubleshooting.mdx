# Troubleshooting

Sushi reports problems on the line just above the bottom bar, or at the bottom of the library when it is open.

## macOS will not open Sushi

This build is not notarized yet. If macOS says it cannot verify Sushi, open **System Settings → Privacy & Security**, find the message about Sushi near the bottom and click **Open Anyway**. macOS asks once.

Sushi needs a Mac with Apple Silicon and macOS 26 or later.

## The shortcut does not work

Sushi shows the panel on **Caps Lock**: while it runs, it maps Caps Lock to a key no keyboard has and listens to that key. It needs no permission, and quitting Sushi gives Caps Lock back. The menu bar menu shows the key in use.

| Message | What to do |
| --- | --- |
| *Caps Lock switches input sources on this Mac, so ⌃⇧Space shows Sushi.* | macOS uses Caps Lock to change the keyboard layout. Turn off **Use the Caps Lock key to switch to and from ABC** in System Settings → Keyboard → Input Sources → Edit, then turn **Use Caps Lock** off and on again in the menu bar menu. Or keep it and use ⌃⇧Space. |
| *Another app already remaps Caps Lock, so ⌃⇧Space shows Sushi.* | Another tool owns Caps Lock, for example Raycast's Hyper Key or a `hidutil` mapping. Turn that off, then turn **Use Caps Lock** off and on again; or keep ⌃⇧Space. |
| *Could not register …: …* | Another app holds that key combination. Free it there, or set another combination as `shortcut` in `hotkey.json` in the settings folder and turn **Use Caps Lock** off and on again. Until then, **Show Sushi** in the menu bar menu opens the panel. |
| *hotkey.json: …* | The file is not valid. Sushi uses Caps Lock with ⌃⇧Space as the fallback until you fix it; see [Change the key](/guide/keyboard/#change-the-key). |

To keep Caps Lock for capitals, turn **Use Caps Lock** off in the menu bar menu: ⌃⇧Space then shows the panel, or the combination you put in `hotkey.json`.

If the panel shows but ignores keys, click inside it: a panel that is visible but not active does not receive keys.

## Edits fail

| Message | What to do |
| --- | --- |
| *Ollama is not installed on this Mac. Download Ollama* | Sushi found neither the Ollama app nor the `ollama` command. Click **Download Ollama** to open the download page, install the app, then download the model. |
| *Install the local model with ollama pull qwen3.5:4b-mlx* | Click the command to copy it, run it in Terminal, and edit again once the download finishes. |
| *Start Ollama on this Mac and try again.* | Sushi could not start Ollama in time. Open the Ollama app, wait until its icon appears in the menu bar, and edit again. |
| *Ollama did not start. Run ollama serve and try again.* | Only the command-line tool is installed, and the server Sushi started did not answer in time. Click the command to copy it, run it in Terminal and leave that window open, then edit again. |
| *Editing requires the local model qwen3.5:4b-mlx.* | The model Ollama offers under this name is not a local copy, for example one forwarded to a cloud service. Remove it with `ollama rm qwen3.5:4b-mlx` and pull it again. |
| *Select a shorter passage. The text and instruction must fit within 12 KB.* | Select the part you want to change instead of the whole prompt, or shorten your instruction. |
| *The model reached its context limit. Select a shorter passage.* | The same: edit a shorter part. |
| *Local Ollama request failed: …* or *Invalid response from local Ollama: …* | Check that Ollama runs: `curl --noproxy '*' -fsS http://127.0.0.1:11434/api/version`. Restart the Ollama app if it does not answer. |
| *The local model returned an empty response.* or *The model returned an empty edit.* | Try again, or reword the instruction. |
| *No changes* | The model found nothing to change, or the prompt already starts with `/goal `. |
| *Write a prompt first* | The prompt, or the selection, is empty. |

The first edit after Ollama starts takes longer while the model loads. Pressing **⌘K** with Ollama already running loads the model ahead of time. [Local model →](/guide/model/)

## Copying fails

*Could not copy the text to the macOS clipboard.* The prompt stays in the panel and the panel stays open. Try **⌘↵** again.

*Could not save the draft: …* The panel's draft storage is full even after Sushi dropped the middle of a long version chain. The panel will not hide on **Esc** or **⌘↵**, so the text is not lost: select it, copy it with **⌘C**, then start a new prompt with **⇧⌘↵** or by replacing all the text.

## Settings files

Errors in your files name the file and the entry, for example:

| Message | Fix |
| --- | --- |
| *rules.json: entry 3 needs exactly one of 'instruction' or 'prefix'.* | Keep one of the two fields in that entry. |
| *rules.json: entry 3 contains an empty field.* | Fill in `id`, `name`, the instruction or prefix, and every alias, or remove the empty alias. |
| *rules.json: duplicate rule ID 'shorten'.* | Give each action its own `id`. |
| *dictionary.json: entry 2 needs both 'from' and 'to'.* | Fill in both. |
| *dictionary.json: duplicate source 'mac whisper'.* | Spoken forms must differ, ignoring case. |
| *Enter an absolute library directory in library-path.txt.* | Write a full path starting with `/`, or delete the file to use the default library. |

Sushi reads the files again each time the panel appears, so a fixed file takes effect the next time you open it. The message stays until then. [Library and files →](/guide/library/#your-files)

## Report a problem

[Open an issue](https://github.com/octopot/sushi/issues/new) with the message, what you did just before it, and your macOS version. Leave your prompt text out unless it is needed.
