# Troubleshooting

Sushi reports problems on the line just above the bottom bar, or at the bottom of the library when it is open.

## macOS will not open Sushi

This build is not notarized yet. If macOS says it cannot verify Sushi, open **System Settings → Privacy & Security**, find the message about Sushi near the bottom and click **Open Anyway**. macOS asks once.

Sushi needs a Mac with Apple Silicon and macOS 26 or later.

## Sushi starts and nothing appears

That is how it starts: the icon in the menu bar and the key, without the panel. Press **Caps Lock**, choose **Show Sushi** in the menu bar menu, or open Sushi again while it runs. Only the very first start shows the panel by itself.

## The shortcut does not work

Sushi shows the panel on **Caps Lock**: while it runs, it maps Caps Lock to a key no keyboard has and listens to that key. It needs no permission, and quitting Sushi gives Caps Lock back. **Show Sushi** in the menu bar menu shows the key in use. When it is not the key you chose, a row under it, such as **Caps Lock unavailable…**, opens Settings ▸ Keyboard, which says why and what to do.

| Message | What to do |
| --- | --- |
| *Caps Lock switches input sources on this Mac, so ⌃⇧Space shows Sushi.* | macOS uses Caps Lock to change the keyboard layout. Turn off **Use the Caps Lock key to switch to and from ABC** in System Settings → Keyboard → Input Sources → Edit (**Open macOS keyboard settings…** in Settings ▸ Keyboard goes there), then come back to Settings: Sushi takes Caps Lock again. Or keep it and use the shortcut. |
| *Another app already remaps Caps Lock, so ⌃⇧Space shows Sushi.* | Another tool owns Caps Lock, for example Raycast's Hyper Key or a `hidutil` mapping. Turn that off, then come back to Settings ▸ Keyboard, or quit Sushi and open it again; or keep the shortcut. |
| *Could not register …: …* or *No key shows Sushi* | Another app holds that key combination. Free it there, or record another one in Settings ▸ Keyboard. Until then, **Show Sushi** in the menu bar menu opens the panel. |
| *hotkey.json: …* | The file is not valid. At launch Sushi uses Caps Lock with ⌃⇧Space as the fallback until you fix it. Settings ▸ Keyboard shows the error and can [start over](/guide/settings/#when-a-file-is-broken); see [Change the key](/guide/keyboard/#change-the-key). |

To keep Caps Lock for capitals, choose **Keyboard shortcut** in Settings ▸ Keyboard: ⌃⇧Space then shows the panel, or the combination you record there.

If the panel shows but ignores keys, click inside it: a panel that is visible but not active does not receive keys.

## The panel hides when Writing Tools opens

On a Mac with Apple Intelligence, selecting text in the panel offers Writing Tools. Sushi 0.2.1 hid the panel when a Writing Tools window, such as the one **Summary** opens, took the keyboard, and the next Caps Lock showed the panel only for a moment. From 0.3.0 the panel stays open under that window and hides when you click another app or press Caps Lock; the next show brings the window back in front, and once you close it, typing goes to the panel again.

If the panel still hides by itself, turn on **Log panel activity** in Settings ▸ About, repeat what hid the panel, and send the log, which **Show log** shows in Finder, with a [problem report](/guide/report/).

## Edits fail

| Message | What to do |
| --- | --- |
| *Ollama is not installed on this Mac. Download Ollama* | Sushi found neither the Ollama app nor the `ollama` command. Click **Download Ollama** to open the download page, install the app, then download the model. |
| *Install the local model with ollama pull qwen3.5:4b-mlx* | Click the command to copy it, run it in Terminal, and edit again once the download finishes. |
| *Start Ollama on this Mac and try again.* | Sushi could not start Ollama in time. Open the Ollama app, wait until its icon appears in the menu bar, and edit again. |
| *Ollama did not start. Run ollama serve and try again.* | Only the command-line tool is installed, and the server Sushi started did not answer in time. Click the command to copy it, run it in Terminal and leave that window open, then edit again. |
| *Editing requires the local model qwen3.5:4b-mlx.* | The model Ollama offers under this name is not a local copy, for example one forwarded to a cloud service. Remove it with `ollama rm qwen3.5:4b-mlx` and pull it again. |
| *Select a shorter passage. The text and instruction must fit within 12 KB.* | Select the part you want to change instead of the whole prompt, or shorten your instruction. |
| *The model reached its context limit. Select a shorter passage.* | The same: edit a shorter part. |
| *Local Ollama request failed: …* or *Invalid response from local Ollama: …* | Check that Ollama runs: `curl --noproxy '*' -fsS http://127.0.0.1:11434/api/version`. Restart the Ollama app if it does not answer. |
| *The local model returned an empty response.* or *The model returned an empty edit.* | Try again, or reword the instruction. |
| *No changes: the model returned the text as it was* | The model answered with the same text: it found nothing to change, or it would not change the meaning. Press **⌘K** and name the change exactly, such as *replace X with Y*. |
| *No changes* | The prompt already starts with `/goal `. |
| *Write a prompt first* | The prompt, or the selection, is empty. |

The first edit after Ollama starts takes longer while the model loads. Pressing **⌘K** with Ollama already running loads the model ahead of time. [Model →](/guide/model/)

With OpenRouter, OpenAI or Claude in use, a failed edit ends with **Edit with Ollama**, and a key that no longer works offers **Connect again**. [When a hosted edit fails →](/guide/model/#when-a-hosted-edit-fails)

## Copying fails

*Could not copy the text to the macOS clipboard.* The prompt stays in the panel and the panel stays open. Try **⌘↵** again.

*Could not save the draft: …* The panel's draft storage is full even after Sushi dropped the middle of a long version chain. The panel will not hide on **Esc** or **⌘↵**, so the text is not lost: select it, copy it with **⌘C**, then start a new prompt with **⇧⌘↵** or by replacing all the text.

## Settings files

Errors in your files name the file and the entry, for example:

| Message | Fix |
| --- | --- |
| *rules.json: entry 3 needs exactly one of 'instruction' or 'prefix'.* | Keep one of the two fields in that entry. |
| *rules.json: entry 3 contains an empty field.* | Fill in `id`, `name`, the instruction or prefix, and every alias, or remove the empty alias. |
| *rules.json: duplicate rule ID 'shorten'.* | Give each action its own `id`. |
| *dictionary.json: entry 2 needs both 'from' and 'to'.* | Fill in both. |
| *dictionary.json: duplicate source 'mac whisper'.* | Spoken forms must differ, ignoring case. |
| *Enter an absolute library directory in library-path.txt.* | Write a full path starting with `/`, or delete the file to use the default library. |
| *model.json: …* | Fix the field it names, or delete the file to edit with Ollama. Settings ▸ Model writes the file for you. |
| *diagnostics.json: …* | The file holds one field, `record`, true or false. Fix it, or delete it to stop recording; **Log panel activity** in Settings ▸ About writes it for you. |

Sushi reads the files again each time the panel appears, so a fixed file takes effect the next time you open it. The message stays until then. Settings shows the same message in the file's pane and can start that file over from the defaults, keeping the broken one next to it. [Settings →](/guide/settings/#when-a-file-is-broken)

An invalid `dictionary.json` no longer stops your actions, and an invalid `rules.json` no longer hides the dictionary.

## Report a problem

Choose **Report a problem…** in the menu bar menu or in Settings ▸ About: Sushi puts together a report with your description, the build and its own state, leaving your prompts, files and keys out, and you send it yourself. When the panel does not stay open, send the build info and the log from Settings ▸ About instead. [Report a problem →](/guide/report/)

To say only which build you run, choose **About Sushi** in the menu bar menu and click **Copy build info**: it copies a short block with the version, the commit and your macOS version.
